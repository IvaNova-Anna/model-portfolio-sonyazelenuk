# Дизайн — сайт-портфолио модели

Дата: 2026-08-18
Статус: утверждён
Источник требований: [spec.md](../../../spec.md)

## Что строим

Одностраничный сайт-портфолио начинающей модели в тёмной editorial-эстетике.
Главный сценарий: агент открывает ссылку с телефона, видит баннер с именем,
листает фото, читает компкарт, пишет в Telegram.

Документ фиксирует решения, принятые поверх `spec.md`. Там, где он расходится
со спекой, действует этот документ — расхождения перечислены в конце.

## Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Язык сайта | Только английский. Кириллица в шрифтах не нужна, двуязычность снята |
| Контакты | Только Telegram. Телефон не публикуем |
| Список фото | Build-команда на хостинге, без GitHub Action |
| Сетка галереи | Masonry без обрезки кадров |
| Инструменты медиа | `avconvert` (в macOS) и Pillow вместо ffmpeg и cwebp |

## Структура проекта

```
landing_3/
├── index.html          разметка: пять секций
├── style.css           типографика, сетки, палитра, анимации
├── app.js              лайтбокс, свайп, masonry, Intersection Observer
├── content.js          имя, компкарт, Telegram — единственное место с данными
├── photos.json         генерируется при сборке, руками не трогается
├── photos/             WebP-фото, имена с префиксом 01-, 02-, …
├── video/              hero.mp4 + poster.webp
├── fonts/              два .woff2, self-hosted
├── build-photos.js     генератор photos.json
├── netlify.toml        команда сборки
└── docs/superpowers/   спека и дизайн
```

Проект — отдельный git-репозиторий внутри `landing_3`. Домашняя папка
`/Users/annaivanova` сама является git-репозиторием с посторонней историей,
поэтому без `git init` коммиты сайта смешались бы с ней.

### Разделение ответственности

- `content.js` знает данные
- `style.css` знает внешний вид
- `app.js` знает поведение
- `photos.json` знает файлы

Правка параметров компкарта трогает один файл из десяти строк. Правка
типографики не может задеть лайтбокс. Это ответ на риск №2 из спеки:
AI-правки не должны ломать соседние фичи.

### build-photos.js

Единственный код, выполняемый не в браузере. Проходит по `photos/`, сортирует
по имени, читает ширину и высоту из заголовка каждого WebP, пишет:

```json
[{"src": "photos/01-look.webp", "w": 1200, "h": 1600}]
```

Без зависимостей и без `npm install`: Node на Netlify есть, формат заголовка
WebP разбирается двадцатью строками. Локально запускается вручную, чтобы
галерея работала до деплоя.

Размеры нужны, чтобы браузер зарезервировал место под каждое фото и страница
не дёргалась при подгрузке.

## Секции страницы

### Hero

Видео на весь экран: `muted autoplay loop playsinline preload="metadata"`,
атрибут `poster` с постер-кадром. Поверх — имя латиницей крупным serif, под ним
тонкая строка-подпись (город) и указатель вниз.

`playsinline` обязателен: без него iOS открывает видео отдельным
полноэкранным плеером вместо фонового автоплея.

Постер — не заглушка на время загрузки, а полноценное второе состояние: в
режиме энергосбережения на iPhone автоплей не запускается никогда. Поэтому имя
и подпись живут в HTML поверх видео, а не вшиты в кадр.

### Галерея

Masonry на JS: 2 колонки на телефоне, 3 на десктопе, 4 на широких экранах.
Скрипт кладёт очередное фото в самую короткую колонку, сохраняя порядок слева
направо — CSS `columns` не подходит, он уводит порядок 1-2-3 вниз левого
столбца и ломает принцип «лучшее фото первым».

Первые два фото — `loading="eager"` (попадают в первый экран после hero),
остальные `loading="lazy"`.

### Лайтбокс

Тап открывает фото на весь экран. Свайп влево-вправо листает, свайп вниз или
тап по фону закрывает. На десктопе — стрелки и Esc, с возвратом фокуса на то
фото, откуда открыли. Пока лайтбокс открыт, фон не скроллится.

Реализация на нативных `touch`-событиях, без библиотек. Порог свайпа ~50 px,
всё остальное считается тапом.

### Компкарт

Строгий двухколоночный список: Height, Bust, Waist, Hips, Dress, Shoes, Hair,
Eyes. По-английски, сантиметры, обувь EU. Значения из `content.js`. Ничего
декоративного: агент считывает цифры за три секунды.

### Контакты

```
              B O O K I N G

   Available for editorial, commercial,
        runway and lookbook work.

        [ Message on Telegram ]
```

Формулировка говорит о готовности к съёмкам, а не об опыте, — корректна для
начинающей модели. Разметка блока рассчитана на список из нескольких контактов:
добавить телефон, почту или агента = добавить объект в `content.js`.

### Анимации

Один приём на весь сайт: секция при появлении в кадре всплывает на 20 px и
проявляется за 0.6 с. Intersection Observer, срабатывает один раз.
Под `prefers-reduced-motion` анимации выключаются.

### Служебное

`title` вкладки с именем модели, фавикон, OpenGraph-теги с превью-картинкой,
alt-тексты на всех фото.

OpenGraph перенесён из nice-to-have в MVP: главный сценарий — отправить ссылку
в Telegram, а без превью она выглядит голой строкой. Цена — шесть строк в
`<head>` и одна картинка.

## Медиа-пайплайн

Ни ffmpeg, ни cwebp, ни Homebrew на машине нет. Всё нужное уже в системе.

### Фото

Скрипт на Pillow 11.3: даунскейл по длинной стороне до 1600 px, конверт в WebP
с качеством ~82, вычистка EXIF. Принимает любые форматы, включая HEIC.

Вычистка EXIF обязательна: в снимках с телефона лежат GPS-координаты места
съёмки, публиковать их на сайте модели нельзя.

Ожидаемый вес — 200–350 КБ на кадр.

### Видео

`avconvert --preset Preset1920x1080 --multiPass`, обрезка через
`--start` / `--duration` до 12–15 секунд. Если после первого прохода файл не
влезает в 6 МБ, спускаемся до 720p: в фоновом видео на весь экран разница на
телефоне неразличима, вес падает вдвое.

Длительность — настоящее ограничение, а не разрешение: 1080p H.264 в 6 МБ это
примерно 15–20 секунд.

`avconvert` не умеет удалять звуковую дорожку. При `muted` в плеере она весит
~100 КБ на 15 секунд и в бюджет вписывается.

Постер — кадр из этого же видео, в WebP.

### Бюджет первого экрана

Видео 6 МБ + постер + два шрифта + два первых фото ≈ 7 МБ. Поэтому видео
получает `preload="metadata"`: браузер показывает постер и грузит текст,
видео подтягивается следом. Страница читаема примерно за секунду.

## Публикация

1. `git init` в `landing_3` (сделано)
2. Репозиторий на GitHub
3. Netlify подключается к репозиторию: команда сборки `node build-photos.js`,
   папка публикации — корень
4. Пуш в `main` обновляет сайт, пуш в ветку даёт preview-ссылку

Аккаунты GitHub и Netlify уже есть.

Обновление фото моделью: загрузить файл через веб-интерфейс GitHub с телефона
(Add file → Upload) → Netlify пересобирает → фото на сайте. Порядок задаётся
числовым префиксом в имени файла — единственное правило, которое нужно помнить.

## Проверка

Чек-лист прогоняется после каждой правки, через браузер:

1. Баннер играет (и корректно выглядит с одним постером, без видео)
2. Галерея открывается, фото не прыгают при загрузке
3. Свайп листает, Esc и стрелки работают на десктопе
4. Компкарт читается
5. Кнопка Telegram ведёт по нужному адресу
6. Всё то же в окне шириной 375 px

## Порядок работы

Сначала каркас с плейсхолдерами вместо фото — так проверяется вёрстка и
выбирается шрифт, не дожидаясь медиа. Потом подставляются реальные файлы.

Шрифт выбирается по живому макету: одна CSS-переменная, 3–4 пары кандидатов
из списка спеки. Кириллица не нужна, поэтому выбор шире, чем предполагала
спека.

## Расхождения со spec.md

| Спека | Дизайн | Причина |
|---|---|---|
| `photos.json` через GitHub Action | Build-команда на хостинге | Единственная движущаяся часть стека; требует прав на запись, порождает лишний деплой |
| RU-контент, EN в nice-to-have | Только EN | Компкарт — цифры и десяток слов; международный формат понятен и русским агентствам |
| Telegram + телефон | Только Telegram | Публичный номер собирают боты, отозвать нельзя; ник в Telegram меняется за минуту |
| OpenGraph в nice-to-have | OpenGraph в MVP | Лежит на главном пути пользователя, стоит шесть строк |
| ffmpeg и cwebp | `avconvert` и Pillow | Уже в системе; Homebrew не установлен |
| Видео ≤6 МБ, 1080p | Плюс: длительность ≤15 с | Без ограничения длительности требование к размеру невыполнимо |
| Постер «на время загрузки» | Постер как запасное состояние | В энергосбережении на iOS автоплей не работает никогда |

## Вне области MVP

Двуязычность, блок агента, свой домен, раздел с дополнительными видео,
скачиваемый PDF компкарта, Decap CMS.
